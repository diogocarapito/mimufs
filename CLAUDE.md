# CLAUDE.md — mimufs

mimufs is an open-source (GPL-3.0) desktop app for macOS, Windows and Linux. It guides Portuguese family-medicine clinicians step by step through extracting MIM@UF reports and the SClínico appointments PDF, validating them, merging them into one patient-level dataset, cleaning it, and exporting tables. **Everything runs locally.** The only network call is an optional update check.

## Stack (decided, don't re-litigate)

Python 3.12 · PySide6 (`pyside6-essentials`, Qt Widgets, Fusion style + QSS tokens) · Polars · DuckDB (one `.mimufs` file per project) + pyarrow · openpyxl (with Diogo's compat patch) · xlrd (legacy BIFF fallback only) · tabula-py + bundled jlinked JRE · PyYAML + pydantic v2 · XlsxWriter · platformdirs · truststore · **Briefcase** for packaging · GitHub Actions · GitHub Pages (`site/`, plain HTML) on mimufs.com.

## Non-negotiable rules

1. **No data leaves the machine.** No telemetry, analytics, crash reporting, remote fonts, QtNetwork or QtWebEngine. The only outbound request is `GET https://mimufs.com/version.json` in `mimufs.update`. `mimufs.netguard` (a `sys.addaudithook`) is installed first in `__main__`. DuckDB extension auto-install and auto-load are off.
2. **No real patient data in the repo, ever.** Fixtures are synthetic and generated by `tests/fixtures/make_fixtures.py`. Never commit `.xls`/`.xlsx`/`.pdf`/`.mimufs` files outside `tests/fixtures/generated/` (git-ignored). The one allowed exception is `docs/reference/MIMUF_Header_examples.xlsx` (headers only, anonymised). Logs must never contain patient IDs, names or values.
3. **`mimufs.core` never imports Qt.** The GUI is a thin layer that runs core functions in worker threads (`QThreadPool`).
4. **Never destroy data.** Keep raw imports byte-identical in `raw/`. Every correction keeps the original value and writes to `audit_log`.
5. **Configuration over code.** Reports and cleaning rules live in YAML (`core/specs/`), validated by pydantic. Adding a report should not need new Python.
6. **Language**: UI strings in **PT-PT**, centralised in `gui/strings_pt.py` and the report YAML. Code, comments, docs, commits in **English**.
7. **Status is never colour-only**: always icon + colour + label.
8. Don't trust file extensions: sniff bytes (TECH_SPECS §5.0).

## Commands

```bash
uv sync                                  # install deps (dev included)
uv run ruff check . && uv run ruff format --check .
uv run mypy src/mimufs/core
uv run pytest                            # unit + golden + offline e2e
uv run python tests/fixtures/make_fixtures.py   # regenerate synthetic fixtures
uv run briefcase dev                     # run the app from source
uv run briefcase create && uv run briefcase build && uv run briefcase run   # run the bundle
```

Keep these working; update this section if a command changes.

## How to work

- Follow the milestones in TECH_SPECS §18, **starting with M0**. Don't start a milestone before the previous one's "Done when" holds.
- **Before restructuring**, tag the current state of the repo `legacy-autogui` (the old pyautogui/Nuitka experiment) and remove `pyautogui`, `opencv-python`, `Nuitka`, `requests` and the `Dockerfile` (TECH_SPECS §1.2).
- Write tests with the code. Every validation check (V/S/J) needs a fixture that triggers it and a test asserting its status and PT-PT message.
- The offline e2e test (`tests/e2e/test_pipeline_offline.py`) must pass on all 3 OSes before any milestone is called done.
- Small, focused commits (Conventional Commits: `feat:`, `fix:`, `test:`, `docs:`, `chore:`). Branch per milestone; don't push to `main` without Diogo's OK.
- Keep `docs/PRD.md` and `docs/TECH_SPECS.md` in sync with decisions made while building, in the same commit as the code that changes them.

## Domain glossary

- **MIM@UF**: the SNS monitoring platform the reports come from. **SClínico**: the EHR (appointments PDF). **USF/UCSP**: family health unit. **MF / Médico de Família**: family doctor. **NOP**: operational patient number, used when the SNS number is missing. **Utente**: patient (9-digit SNS number = main key). **ICPC-2**: primary-care classification of problems. **Slot**: one required extraction of a report (a month, a quarter, a Tipo Dado, an ICPC set). **Rever e continuar**: the gate sub-step that ends each phase.
